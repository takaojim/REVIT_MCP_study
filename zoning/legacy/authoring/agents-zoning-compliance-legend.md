# 都市計畫土地使用分區管制規則（土管）圖例檢討表格自動排版系統

本技能律定臺灣都市計畫法規圖例檢討表格（Zoning Compliance Legend）在 Autodesk Revit 中的**標準單頁滿版雙欄公版模矩**、**嚴格 50.0 滿版全字元微度量矩陣**、**真實物理行距（6.60mm 線性物理常數）盒模型**、**條款級跨欄拆分接續演算法** 與 **專案啟動工程原則**。

---

## 🧭 0. 專案啟動工程原則與踩坑教訓 (Core Engineering Principles)

> [!IMPORTANT]
> **嚴禁草率猜測、嚴禁模糊經驗值、不確定就主動詢問使用者！**
>
> 1. **物理常數必須先精確測定，再啟動邏輯建模**：
>    過去將 Revit 文字行距誤設為 `5.80mm` 與 `6.20mm`（經驗估算值），在 1~3 行短條文時因底部留白被掩蓋，但在 8~18 行長條文時累積誤差高達 $7.2\text{mm}$，導致橫線切字。
>    經 Revit 字型排版引擎（Windows DirectWrite / TrueType Typography）嚴格測定：
>    $$\text{Line Height Ratio} = 2.20 \times \text{字高 (3.0mm)} = \mathbf{6.60\text{ mm}}$$
>    **此為純線性常數（Linear Constant），經 18 行、30 行、50 行實體驗證，每一行皆嚴格呈 $6.60\text{mm}$ 等差數列收斂，未來絕不再改！**
> 2. **嚴格拒絕模糊彈性，鎖定唯一物理天花板（50.0）**：
>    有效排版寬度 214.0mm / 4.25mm 中文字寬 = 50.35 字。母容量上限嚴格鎖死為 **`50.0`**，絕不退縮！
> 3. **主動回饋與確認**：
>    當遇到跨欄臨界點、特殊表格排版或規範不明確時，**必須即時向使用者請示確認，嚴禁私自猜測走偏路！**

## 📐 3. 真實物理行距（6.60mm 線性常數）盒模型與段落切線公式

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 段落頂部基準線 (startY)                                  │
│    │── PAD_TOP (2.00 mm)                                    │
│ 2. TextNote 插入錨點 (y = startY - 2.00 mm)                 │
│    │                                                        │
│    │  [第 1 行文字] ─── 行高 3.00 mm                        │
│    │  [行間距 Leading] ─── 3.60 mm (真實 Line Pitch = 6.60 mm)│
│    │  [第 N 行文字] ─── 文字底端 (Descender)                │
│    │                                                        │
│    │── PAD_BOTTOM (4.00 mm，文字底端至橫線淨空 = 2.00 mm)   │
│ 3. 段落底部分隔線 (Line Y = startY - SectionHeight)         │
└─────────────────────────────────────────────────────────────┘
```

* **段落總高度代數公式（任意 $N$ 行完全適用）**：
  $$\text{SectionHeight} = \mathbf{2.00\text{ mm}} + N_{\text{lines}} \times \mathbf{6.60\text{ mm}} + \mathbf{4.00\text{ mm}} = N_{\text{lines}} \times 6.60 + 6.00\text{ mm}$$
* **切線位置**：每一條水平分隔線永遠精確劃在段落最後一行文字下方 $4.00\text{mm}$（淨空 $2.00\text{mm}$），無論條文是 5 行、18 行、30 行或 50 行，**切字與段落重疊 100% 徹底根除**。

## ✂️ 4. 條款級跨欄拆分接續演算法 (Item-Level Cross-Column Splitting)

當法條總長度超過左欄可用空間（$500.67\text{mm}$）時，**嚴禁草率將整條法規跳到右欄**（這會造成左欄底部留下幾十毫米的巨大空白）。必須執行嚴謹的「條款級子拆分」：

1. **左欄最大化收納（Part A）**：
   * 前言 ＋ 子款項（如 `（一）`、`（二）`、`（三）之 1 與 2`）。
   * 貼緊左欄底線（留白控制在 $5\sim 15\text{mm}$，達到極致滿版）。
2. **右欄接續排列（Part B）**：
   * 法條欄標註：**`[條號]、\n(續)`**（例如 `十三、\n(續)`）。
   * 內容欄接續承接剩餘子款項（如 `3. 商業區...`、`（四）...`、`（五）...` ＋ 審議要件）。
   * 銜接後續條文，兩欄皆達到視覺平衡與極致工整。

## 📊 5. 條文內嵌子表格標準 (Sub-Table Architecture)

1. **表格範圍**：僅置於 220mm 條文欄內，左右各內縮 3mm（有效寬 214.0mm）。
2. **儲存格自動折行**：每個儲存格依該欄淨寬度 $w_c - 4.0\text{mm}$ 自動折行。
3. **表頭高度**：固定 **`8.0 mm`**。
4. **資料列高**：$\max(N_{\text{cell\_lines}}) \times 6.60 + 4.00\text{ mm}$。
