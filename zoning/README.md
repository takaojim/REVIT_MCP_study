# 土管圖例製作與獨立檢核

目前採第一階段：人工交接，Antigravity IDE 製作，Codex 獨立檢核。沒有啟用排程、監控或自動迴圈。

## 資料位置

| 區域 | 用途 |
|---|---|
| [製作技能](skills/zoning-legend-author/SKILL.md) | 辨識原文、計算段落與表格尺寸、建立或修正圖例 |
| [檢核技能](skills/revit-legend-pdf-audit/SKILL.md) | 自行出圖，比對原始 PDF，標示錯字與漏列；不修模型 |
| [和美](plans/和美細部計畫-土地使用分區管制要點/task.md) | 原始 PDF、舊製作資料、第一輪匯出／註記／修正交接 |
| [潭子](plans/擬定臺中市潭子地區都市計畫細部計畫-土地使用管制/task.md) | 原始 PDF、舊製作資料與歷史報告 |
| [霧峰](plans/霧峰地區都市計畫細部計畫-第一次通盤檢討/task.md) | 原始 PDF 與舊製作資料 |
| [歷史資料](legacy/README.md) | 無法確認所屬計畫的快照，以及兩份不一致的舊製作規範 |

各計畫以土管名稱命名，固定放置 `source/`（原始依據）、`task.md`（中立任務）、`execution/`（製作私有工作資料）、`reviews/round-NN/`（每輪檢核證據）。有新一輪才建立新目錄，不覆蓋舊 PDF。

## 角色界線

製作者可讀原始文件、任務、自己的工作資料與修正交接。檢核者只讀指定原始 PDF、中立任務、當次 Revit 圖例及自己產生的證據；不得查看製作腳本、解析 JSON、排版計算、製作者自評或 `legacy/`。複檢先獨立比對全文，再對照前輪問題確認有無修正。

資料夾分類與技能是工作規則，不是檔案權限隔離。需要嚴格盲檢時，以全新檢核任務啟動，只提供允許的輸入；避免把製作者對話轉貼給檢核者。根目錄與本說明不列具體錯誤答案。

## 人工交接順序

1. 使用者在 `task.md` 指定原始版本、確切圖例名稱與版型要求。原始 PDF 不覆寫；疑似原文錯字須保留並另記，不能自行改成推測內容。
2. Antigravity 製作或依交接修正，保存模型並將製作紀錄放 `execution/`；完成後停止其 MCP 連線及自動重連。
3. 使用者切換至 Codex，必要時在 Revit 按「切換／釋放連線」。確認由 Codex 取得連線後，才開始檢核。兩個介面可開著，但不能同時搶占 MCP。
4. Codex 自行匯出完整圖例至新一輪 `reviews/round-NN/`；確認 PDF 完整後釋放連線，再以原始文件做文字／表格比對。
5. 每輪保留原始匯出 PDF、給人看的螢光註記 PDF、給 agent 的 `修正交接.md`。交接內合併範圍、結論、錯誤清單及未能確認項目，不再另製重複的文字檢核報告。無錯誤不用製造空白註記版。
6. 使用者看完交接後，決定是否派 Antigravity 修正。修正完成再人工切換回 Codex。全部核對通過才結案；來源不清、無法出圖或問題反覆不收斂時暫停交由使用者處理。

## 換電腦接續

- 提交時包含本次 `zoning/` 搬移刪除與新增、技能入口、專案指引、必要路徑調整與 log；檢查差異後自行 commit／push。不要把無關 scratch、帳密或本機設定一起提交。
- 另一台 pull 後，從本頁與指定計畫的 `task.md` 開始。技能正本在 repo 內，不依賴此電腦的個人技能安裝；可直接要求 agent 讀取相應 `SKILL.md`。若 IDE 未自動發現技能，明確提供此路徑。
- Git 不會同步正在開啟的 Revit 模型或載入中的外掛。本次沒有打包 RVT；請另外取得正確模型，完成該台 Revit 外掛與 MCP client 設定並驗證連線。
- Revit 必須開啟正確模型、MCP 服務啟動；原生 UI 出圖需要可互動桌面。檢核助手需 Python 與 `pdfplumber`；依該環境安裝，不沿用其他電腦的絕對路徑。
- 所有 Revit view/type/element ID 必須現查。舊資料中的 ID、字型與尺寸不保證跨模型可用。

### 啟動提示

製作：讀取 `zoning/skills/zoning-legend-author/SKILL.md` 與指定計畫 `task.md`，依使用者核定版型製作；若為修正，另讀指定輪次的修正交接。尚未收到製作指示時只做準備。

檢核：在新的 Codex 任務讀取 `zoning/skills/revit-legend-pdf-audit/SKILL.md` 與指定計畫 `task.md`；僅讀指定原始 PDF，自行從 Revit 出圖，檢查文字、條款及表格漏列。不要讀 execution、legacy 或製作者對話，不修改模型。
